# Grok Build に投げるプロンプト

grok.com → モード切替で **Build** を選び、下の枠をそのまま貼る。
1発で動かない場合は、このファイル末尾の「追加指示」を続けて投げる。

---

```
バイナリーオプション用の「次の5分足が上がるか下がるか」を%で出すWebアプリを作れ。スマホでもPCでも使えるダークな金融ダッシュボード。日本語UI。

■ 絶対ルール（破ったら不合格）
- AI・LLM・Grokによる「予想」「推論」「感覚」「ニュース解釈」は一切禁止。画面に出す%はすべて過去OHLCの頻度カウントだけで計算する。
- ローソク足データが取れないときは数字を捏造せず、エラーを出して止める。
- 常にどちらかに賭けさせるUIは禁止。統計的優位がないときは大きく「見送り」と出す。
- 投資助言ではない旨をフッターに小さく書く。

■ データ
- 通貨ペアは1つに絞って分析する。セレクトで切替: USDJPY / EURUSD / GBPJPY / EURJPY / AUDJPY（デフォルトUSDJPY）。
- データ源: Yahoo Finance chart API（APIキー不要）
  GET https://query1.finance.yahoo.com/v8/finance/chart/{SYMBOL}?interval=5m&range=60d
  SYMBOL例: USDJPY=X, EURUSD=X
- ブラウザCORSで直接取れない場合はサーバー側fetch、だめなら corsproxy.io 等のプロキシ。失敗したら「データ取得失敗」と理由を表示し、ダミー足は使わない。
- 足は {t: unix秒, o, h, l, c}。o/h/l/c が null のバーは捨てる。
- 形成中の足（now < t+300）は「直近確定足」から除外する。
- 直近確定足が15分以上前なら「市場クローズ/配信停止。予測中止」と出して計算しない。

■ 統計（この式以外で確率を出すな）

1) 方向: close>open なら陽(U)、close<open なら陰(D)、同値はF（標本から除外）。
2) 予測対象は「確定足 i の次の足 i+1」。i+1.t - i.t !== 300 のギャップ（週末・欠損）は除外。
3) 条件は確定足 i から抽出し、i+1 が陽だった回数 / 標本数 が「その条件の陽線率」。
   条件:
   - 直前1本: 陽線 or 陰線
   - 直前2本: 陽→陽 / 陽→陰 / 陰→陽 / 陰→陰
   - 直前3本: 同様に3本の並び
   - 時間帯(JST): 予測対象足の開始時刻の時台（unix+9h）
   - セッション: 東京9-15 / 欧州15-21 / NY21-2 / 閑散2-9（JST）
   - 連続数: 同方向が何本続いたか（陽線1〜4連続、陽線5+、陰線も同様）。同値は連続を切る
   - RSI(14)ゾーン: Wilder平滑。14本未満はnull。
     <30 売られすぎ / 30-45 / 45-55 中立 / 55-70 / >70 買われすぎ
     avgGain,avgLoss は最初14本の平均、以降 (prev*13 + 今回) / 14
   - 直前足の実体: |c-o| / 全期間平均実体 が <0.5 小 / <1.5 中 / それ以外 大
4) 各条件の陽線率 p=up/n に Wilson 95%信頼区間（z=1.96）:
   denom = 1 + z²/n
   center = (p + z²/(2n)) / denom
   half = z * sqrt(p(1-p)/n + z²/(4n²)) / denom
   lo=max(0,center-half), hi=min(1,center+half)
5) 判定:
   lo>0.5 → ↑50%超え有意
   hi<0.5 → ↓50%割れ有意
   それ以外 → 優位性なし
   さらに期間全体の陽線率を「地合い(ベースレート)」とし、
   lo>base → +地合い超、hi<base → -地合い割れ、それ以外 → 地合い並み
6) 統合推定（これも頻度の加重平均。モデルではない）:
   n>=30 かつ 0<p<1 の条件だけ使う。
   logit = ln(p/(1-p))
   w = n * p * (1-p)
   pooled = 1 / (1 + exp( -(Σ w*logit) / (Σ w) ))
   使える条件がなければ統合は出さない。
7) ペイアウト倍率 P（デフォルト1.88、入力可）の損益分岐勝率 = 1/P。
   edge = max(pooled, 1-pooled)
   「有意な条件が1つ以上」かつ edge > 1/P のときだけ「分岐点超え」と書く。
   それ以外は「期待値マイナス / 見送り」。
   過去頻度は将来保証しない、と必ず書く。

■ 画面
上部: 通貨ペアセレクト / ペイアウト入力 / 「予測する」ボタン / 最終更新時刻JST
タブ2つ:

【予測】（メイン）
- 直近確定足: 時刻JST、始値→終値、陽/陰/同値、現在価格
- 予測対象足の開始時刻
- 巨大な数字: 「上がる XX.X% / 下がる XX.X%」（統合推定）
- 判定バッジをさらに大きく: 「見送り」or「上昇寄り」or「下落寄り」
  見送り条件 = 有意な条件がゼロ、または edge が損益分岐に届かない
- 条件ごとの表: 条件名 | いまの値 | 陽線率 | n | 95%CI | 判定
- 損益分岐勝率との比較一行
- 市場クローズ時は数字を消して警告だけ

【リサーチ】
- 取得本数、期間、ベースレート
- 条件カテゴリごとに、n>=50 の行を陽線率降順で表
  列: 条件値 | 陽線率 | n | 95%CI | vs50 | vs地合い
- 読み方の注記:
  「50%有意は賭けの向きの偏り。地合い超えだけが条件固有の予測力。地合い並みはトレンドの反射で消える」

デザイン: 黒背景、数字は等幅、上昇は緑・下落は赤・見送りは黄。チャートは直近80本の簡易ローソク（ライブラリ可）。ローディング中はスケルトン。予測はボタンでも、起動時にも1回走る。5分ごとに自動再取得するトグル。

実装は全部クライアント（必要なら薄いプロキシ）に閉じる。Grok APIで確率を出してはいけない。コードコメントに「頻度カウントのみ」と書け。
```

## 追加指示（1発目が弱いとき）

数字を捏造したり、Grokが「予想」し始めたらこれを投げる。

```
いま出している%がLLMの予想になっていないか確認して直せ。
確率は必ず「過去60日の同条件での陽線回数÷標本数」だけ。Wilson区間・見送り判定・ダミーデータ禁止を守れ。
YahooがCORSで落ちるならサーバー側fetchに切り替え、失敗時はエラー表示のみ。
```

UIが英語・デスクトップ寄りなら:

```
UIは日本語、スマホ幅375pxでも巨大な%と見送り判定が画面内に収まるように。
```
