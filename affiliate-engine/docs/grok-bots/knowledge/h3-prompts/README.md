# h3-prompts

MiniMax H3 のプロンプトを、動画1本につき1ファイルで置く。

ひな形は [`_template.md`](_template.md)。コピーして `YYYY-MM-DD-<genre>-NN.md` にする。同じ日付の台本が [`../scripts/`](../scripts/) にあれば、ファイル名を揃えて、台本への相対リンクを書く。`_template.md` 自体は動画ではない。

## 誰が書くか

- Grok Build（ナオミチの PC の video-to-h3-prompt）が、参考動画を分析して `prompts.md` にプロンプトを書く。
- Cursor が、その `prompts.md` の該当箇所を、このフォルダのファイルへそのまま写す。文言は直さない。
- 市場リサーチが、投稿後の再生と倍率を日次に書く。
- Cursor が、その実測を「投稿後の実測」へ写し、状態を変える。

プロンプトがまだ無い本のファイルは作らない。空のプロンプトを埋めない。

## 項目

| 項目 | 中身 |
|---|---|
| 元の URL | 分析した参考動画の URL。自分たちの投稿 URL とは分ける |
| 実測した数字 | その参考動画について、research に書いてある再生・倍率・尺・カット・いいね率。無い項目は「不明」 |
| 写したプロンプト | Grok Build の `prompts.md` からの写し。写した日時と、どのファイルのどの節かを1行添える |
| 生成した結果 | 生成したファイル名、生成日、見た目のメモ。再生数はここに書かない |
| 投稿後の実測 | 市場リサーチの日次に出た、自分たちの投稿の再生・倍率・出典 URL。投稿前は「無し」 |
| 状態 | 未検証 / 勝ち / 負け |

状態の意味は [`../README.md`](../README.md) と同じ。参考動画が高倍率でも、自分たちの投稿後の実測が無いあいだは未検証。勝ちへの昇格は、投稿後の実測で伸びたと日次に書かれたときだけ。
