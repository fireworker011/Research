# A8案件別 動画チャンネル — 作業マニュアル / AI指示

この文書は、次の2つの使い方のために書いてある。

1. **人間の作業マニュアル**（1日 15分×4セット）
2. **Cursor / Grok への指示**（各節の「AIに貼る」枠をそのまま貼る）

元アイデアは「提携済みA8案件ごとに特化チャンネルを作り、YouTube / Instagram / TikTok に最適化する」こと。  
**今すぐ全部は始めない。** 同時立ち上げは再生もクリックも成果も判定不能になる。今の本体は YouTube `@pet_story_select` の14日実験（`docs/video-cash-loop.md`）。

判定の数字は `data/video_cash_log.csv` と `output/video/TODAY.md` だけを見る。無い数字は埋めない。

## 使い方（15秒）

- **今日の作業だけ欲しい** → §3 の該当セットを開く
- **ベンチマークを1本分析したい** → §1 のシートを埋める
- **映像を作りたい** → §2 のプロンプトを Grok / Cursor に貼る
- **エージェントに今日の作業を任せたい** → 下のマスター指示を最初に貼り、続けて「今日のセットは A / B / C / D」と書く
- **Grok Bot にエージェントを作る** → スマホから [PHONE.md](grok-bots/PHONE.md) の文を一度貼って送る。以降は GitHub の所定ファイルだけ読む（[FETCH.md](grok-bots/FETCH.md)）。全文が同じならスルー。投稿したら [POSTED.md](grok-bots/POSTED.md)。チャットに md 全文を貼り直すな

### AIに貼る — マスター指示

```
あなたは affiliate-engine の動画係。目的は再生→クリック→成果を切り分けること。月100万やチャンネル量産は語らない。

必読: affiliate-engine/docs/video-cash-loop.md
必読: affiliate-engine/docs/video-channel-playbook.md
必読: .cursor/skills/video-cash-loop/SKILL.md
判定: cd affiliate-engine && node src/video-judge.js --self-test && node src/video-judge.js
今日の判定: affiliate-engine/output/video/TODAY.md
数字の唯一の入力: affiliate-engine/data/video_cash_log.csv
次の3本: affiliate-engine/docs/youtube-next-3.md

やってよい:
- 判定の再掲、CSVの追記案内、次の3本の再掲
- ベンチマーク分析シートの空欄を「観察項目」として出す（数字は発明しない）
- Grok Imagine 用の映像プロンプト、Cursor 用の台本枠（実験中は新作台本を創らない）
- video-semi-auto.js --healing の手順説明

やってはいけない:
- 投稿・予約投稿・固定コメントの代行
- TikTok / Instagram / 新チャンネル / 新エージェントの提案を「今日やること」として出す
- 参考チャンネルの動画・台本・サムネをコピーする
- Shorts の説明欄・コメントに URL を書く
- 使っていない商品の体験談を書く
- 数字が無い行を埋める
- insight.js を動画に使う
- アフィリンクをコミットする
- ジャンル転換

出力形式:
1. いまのフェーズ（実験N日目 / 判定 / やってはいけないこと）
2. ユーザーが指定したセット（A記録 / B制作 / C投稿準備 / D締め）の手順だけ
3. コピー用テキスト（台本・説明文・Imagineプロンプト・CSV1行）
4. 今日やらないこと（1行）
```

## 1. ベンチマーク分析 → 自社の型への落とし込み

コピーしてよいのは **「押せる場所へ、1回だけ誘導する」構造** だけ。  
動画・サムネ・台本・BGM・タイトルの複製はオマージュではない。

### 1-1. 選定（1アカウント、15分）

目標フォロワーの10倍以上、**かつ今日リンクを開いて確認できる**こと。調べられないアカウントは使わない。

| 手順 | やること | やらないこと |
|---|---|---|
| 1 | 自社の目標フォロワーを1つ決める（例: 1,000） | 「有名だから」で選ぶ |
| 2 | 同じジャンル・同じ尺（今はペット×Shorts）で、フォロワーが目標の10倍以上のアカウントを1つ開く | 長尺専門・別ジャンル・別媒体を混ぜる |
| 3 | チャンネルURL、フォロワー数、確認日をシートに書く | フォロワー数を記憶や噂で書く |
| 4 | 直近10本だけ見る。再生の中央値と、商品が出る本の割合をメモする | 「バズってる」だけで成功と書く |
| 5 | 2つ目は選ばない。分析が終わるまで追加しない | 10アカウントの一覧を作る |

今のチャンネル（登録107）で目標を1,000にするなら、ベンチマークは概ね1万フォロワー以上の **ペットShorts**。  
婚活・美容・転職の長尺は参考欄に残してよいが、今の型の置き換えには使わない。

### 1-2. 分析項目（この列だけ埋める）

1アカウント＝1枚。数字は公開ページかスタジオで見た値だけ。空欄のまま残してよい。

### 1-3. 自社アカウントへの反映手順

実験中（14日以内、または判定が `CONTINUE_EXPERIMENT`）は **反映しない**。シートを1枚書いて終わり。既存32本は触らない。次の3本の文言も変えない。

実験が終わったあと、反映は1変数ずつ。

| 順 | 反映するもの | 確認方法 | 止める条件 |
|---|---|---|---|
| 1 | 導線だけ（プロフィールへ1回） | 週クリックが15以上か | 再生が落ちても、固定コメントにURLを足さない |
| 2 | 冒頭3秒の型（問い / 映像 / 文字のどれか1つ） | 直近3本の再生中央値 | 商品CTAが無い最多再生動画の型を量産しない |
| 3 | 本編骨格（あるある3点＋問い、など） | クリックが維持されるか | 体験談や比較したフリを足したくなったら人間承認 |
| 4 | 投稿ペース（週3が上限のまま） | CSVの `videos_published` | 媒体を足して本数を稼がない |

**反映の書き方（自社用、1行）**

```
相手は「[構造]」で視聴を止め、押せる場所へ[回数]回誘導している。
自社では映像を変えず、同じ構造を「[自分の言葉の骨格]」にする。CTAは「詳しくはプロフィールのリンク（PR）」だけ。
```

## 2. Grok / Cursor での制作（投稿は人間）

役割を固定する。Grok を投稿ボットにしない。Cursor に組織図を作らせない。  
ジャンル9体は ASCII の `docs/grok-bots/agents/<id>.md` を raw で読む（[FETCH.md](grok-bots/FETCH.md)）。編集仕様は各ファイル内と `data/video_production.json`。旧 `launch-keys/` は下書き。

| 担当 | やること | やらないこと |
|---|---|---|
| Cursor | 台本枠、説明文、Imagineプロンプト、`video-semi-auto.js`、CSV追記文、判定の再掲 | 新作台本（実験中）、実投稿、リンクのコミット |
| Grok Imagine | 縦型の映像素材（文字なし） | 商品パッケージの偽造、ロゴ、人間の偽レビュー顔、投稿そのもの |
| 人間（スマホ） | 公式アプリで投稿、プロフィールリンク確認、A8とスタジオの数字、CSV追記 | 「比較して選んだ」等の体験文言をAI案のまま出す |

テロップはみ出し・BGM・不自然さの検査は、**週クリック15を超えてから**入れる。

### 2-1. 実験中の最短ルート（新作を創らない）

1. `docs/youtube-next-3.md` の未投稿分を1本開く
2. 映像は既存の癒し型を再利用するか、下の Imagine プロンプトで **文字なし素材** を1本だけ作る
3. 読み上げ／テロップはドキュメントの文言をそのまま使う
4. 末尾に `詳しくはプロフィールのリンク（PR）`
5. 説明文はドキュメントの「YouTube説明文」。URLなし。`#PR` あり
6. YouTube 公式アプリで投稿。固定コメントにURLを置かない
7. 既存32本は編集しない

テキストカードだけなら（ローカル、確認してからキュー。アップロードはしない）:

```bash
cd affiliate-engine
node src/video-semi-auto.js --healing --limit 3
```

`--healing` はペットの癒し型だけを通し、Instagram キューに入れない。

### 2-2. Cursor に貼る — 台本（実験終了後・人間が「新作3本」と書いたときだけ）

```
affiliate-engine の癒しペット Shorts 用に、台本を3本だけ作れ。
必読: docs/youtube-next-3.md の見出し構造を踏襲すること。
制約:
- 映像の型は変えない（ペットのあるある。商品デモにしない）
- 使っていない商品の体験談・比較・購入を書かない。「調べた/まとめた/観察」までにせよ
- URL・商品名・価格・成果報酬を本文と説明文に書くな
- 末尾は必ず1回だけ: 詳しくはプロフィールのリンク（PR）
- 説明文にも URL を置くな。末尾に #PR
- 絶対/必ず/100%/誰でも簡単に月○万、効果効能の断定は禁止
- 各本は読み上げ15〜35秒。質問か二択で閉じる
- 出力は各本とも「テロップ／読み上げ」と「YouTube説明文（URLなし）」の2ブロックだけ
- ファイルに書くのは、人間が「youtube-next-3.md を更新してよい」と言ったあと
```

検品（AIの賢さに依存しない。この順）:

1. URLが本文・説明・コメント案に無い
2. CTAが1回で、文言が `詳しくはプロフィールのリンク（PR）`
3. `#PR` が説明文にある
4. 体験の捏造が無い（「うちの子がこれを買った」「比較して選んだ」は人間承認が要る）
5. 禁止表現が無い（`compliance.js` の絶対/必ず/100%、効果断定、元本保証など）
6. 商品デモになっていない（最多再生は商品動画ではない）

## 3. 日次ルーティン（15分×4）

1日4セット。全部やらなくてよい。**セットAは毎日。** B〜Dは「今日の1本」がある日だけ。  
実験中の上限は週3本。無い日はAとDだけ。

判定ジョブは 06:37 JST 前後。セットAはそれ以降が楽。

### セットA — 記録（毎日・最優先）

見る場所は2つだけ。YouTube スタジオ（その日の再生と公開本数）と A8（クリックと成果）。

| 分 | 操作 |
|---|---|
| 0-5 | YouTube スタジオで昨日の再生と、公開した本数を見る |
| 5-10 | A8 で昨日のクリックと成果を見る。着地商品名は「A8を見たと書けるとき」だけメモする |
| 10-15 | `affiliate-engine/data/video_cash_log.csv` に1行足す。GitHubアプリでよい |

CSV1行（空の数字を創作しない。見た値だけ）:

```
YYYY-MM-DD,<公開本数>,<再生>,<A8クリック>,<成果>,<メモ>
```

メモに書いてよい例: `A8 8月累計9` / `プロフィールCTA入り1本公開`  
書いてはいけない例: 推定再生、推定CVR、月100万までの残り。

### セットB — 制作（週3本まで）

| 分 | 実験中 | 実験終了後（週クリック15以上） |
|---|---|---|
| 0-3 | 次の3本の未投稿を1つ選ぶ | 勝ち型を1つ再利用。新ジャンルは開かない |
| 3-12 | Imagine で文字なし素材1つ、または既存映像 | 同じ |
| 12-15 | テロップとCTAを載せる。説明文をメモアプリに置く | 同じ。検査（はみ出し等）は週15クリック後 |

このセットで投稿ボタンは押さない。

### セットC — 投稿（人間・公式アプリ）

| 分 | 操作 |
|---|---|
| 0-5 | Shortsとしてアップロード。説明文はメモのコピペ。URLが混ざっていないか目視 |
| 5-10 | プロフィールのA8とPR表記を開いて確認。リンク先をリポジトリに書かない |
| 10-15 | 固定コメントにURLを置かない。投稿した事実だけメモする |

Instagram / TikTok への同時投稿はしない。

### セットD — 締め（判定を読む / 分析1枚）

| 分 | 操作 |
|---|---|
| 0-5 | `output/video/TODAY.md` を読む。判定が `CONTINUE_EXPERIMENT` なら型を変えない |
| 5-15 | 余り時間でベンチマークシートを1枚だけ埋める。反映はしない |

Cursor を使うなら、マスター指示のあと「今日はセットD。判定を再掲し、次の3本を再掲せよ。新しい台本は創るな」。

### 曜日の回し方（負担を固定する）

| 曜日 | セット | 目安本数 |
|---|---|---|
| 月 | A +（余りがあればD） | 0 |
| 火 | A + B + C | 1 |
| 水 | A + D（ベンチマーク1枚） | 0 |
| 木 | A + B + C | 1 |
| 金 | A + B + C | 1 |
| 土 | A のみ | 0 |
| 日 | A + D（週次。月100万は語らない） | 0 |

週3本を超えたら、その週の B/C は休む。  
数字が無い週は、制作を増やすのではなくセットAを優先する。

### 週次（日曜のセットD、15分）

`TODAY.md` のゲートだけ見る。

- 実験中 → 何も変えない
- 週15未満で実験終了 → 量産禁止。案件を安い/申込型にするか、長尺1本かは人間が決める

## 5. 駐車場 — 全案件×3媒体（今は着手しない）

`config/links.json` のキーは案件の棚であり、チャンネル開設リストではない。空キーのままチャンネルを量産しない。

| 優先 | 出す条件（全部満たす） | 出すもの（どれか1つ） |
|---|---|---|
| 0 | いま | YouTube ペットShorts の導線実験 |
| 1 | 週15クリックが3週 | 同じ型の週3維持。媒体追加はまだしない |
| 2 | 週50が3週、または人間が「媒体を足す」と書いた | Instagram **または** TikTok の片方。同時に両方は開かない |
| 3 | 優先2の媒体で週15クリック | 次の1案件（人間が `links.json` にURLを入れたキーだけ） |
| 4 | その案件で成果1 | その型の複製。また1案件だけ |

案件をチャンネル化するときの最小設計（開設時に埋める。今は埋めない）:

```
案件キー: （links.json のキー。空なら開設しない）
媒体: （1つ）
視聴者の仕事: 何に困って、何を決める人か（1行）
映像の型: Shortsあるある / 長尺比較 など（1つ）
押せる場所: プロフィール or 概要
CTA文言: 詳しくはプロフィールのリンク（PR）
ベンチマーク: URL（今日確認できる、目標の10倍）
やらない媒体:
```

アカウント設計の詳細コピペ（Threads用）は `docs/account-setup-kit.md`。  
動画チャンネルに流用してよいのはプロフィールの「調べた／まとめた」姿勢と、同日多アカウント開設をしないことだけ。
