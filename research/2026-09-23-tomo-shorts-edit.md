# tomo Shorts 編集手順（2026-09-23）

CW案件 tomo（韓国アイドル Shorts）。司令部が実行する手順。コードは書き換えていない。エージェント定義も触っていない。

対象は1本目。書体とレイアウトが通るまで残り本数に進まない。

## 実行順

1. 書体を正規ルートで決める（下記「書体」）。非公式サイトからは取らない。
2. 1本目を黒帯レイアウトで作り直す（下記「レイアウト」）。
3. テロップを発話に1行ずつ合わせる（下記「テロップ」）。
4. 納品前チェックを全部通してから Drive へ置く。
5. クライアントの確認が返ってから2本目以降。

## 正としないもの（v3）

添付 `build_01.py` とプレビュー2枚は試作。納品形ではない。

- 書体は `MPLUSRounded1c-ExtraBold`。指定の HG創英角ポップ体ではない。プレビューの字形は丸みがある（目視。フォント名の機械判定はしていない）。
- タイトル Y=90 と 185、本文 Y=1520。マニュアルの縦500 / 縦1000ではない。
- プレビュー2枚は顔が枠いっぱい。黒帯は見当たらない（目視）。
- `timing_plan` は文字数の比率で秒を割っている。発話位置は見ていない。

## レイアウト（判定は1つ）

**正は黒帯。縦フルは不採用。**

判定基準はこれだけ。タイトル2行が動画の外側（上の黒）にあり、動画の上端がタイトル2行の直下で止まっている。映像がタイトルの背後まで伸びていたら不合格。

根拠は次の2つ。公開チャンネル3本のフレームは今回測っていない。チャンネルの見た目では判定しない。

- マニュアル: 「上段の2行の直下に動画を差し込みください」。全面に敷いて文字を乗せる指示ではない。
- 参考完成例の既存メモ（`STYLE_FROM_REFS`、2026-09-23。今回その mp4 は再計測していない）: 手話テテは「黒背景中央に縦動画、直上タイトル、本文は下寄り」。

作り方:

- シーケンスは 1080x1920。最背面は黒。
- 動画は拡大して帯を消さない。横長素材は幅を枠に合わせ、上下の余りは黒のまま残す。
- タイトルは黒帯の中。動画に重ねない。
- 本文の位置はマニュアルの「縦1000」。タイトルは「縦500」。
- ソフトへ 500 と 1000 を入れた結果、タイトルが動画に被るなら、被らない位置まで黒帯側へずらす。直下ルールを優先する。ずらした量は1本目のメモに残す。
- 「縦500」「縦1000」が Filmora の画面上端からの px かは未実測（推測）。Premiere は位置の原点が中央なので、数値をそのまま入れると画面外になりうる。Premiere では上端から 500px / 1000px にガイドを引いて置く。1本目は参考 mp4 と横に並べ、タイトルが動画の直上にあることを目で確認する。

下段の色は赤か黄のどちらか。シリーズで固定する。手話の既存メモは黄、手元 ref メモは赤。どちらもマニュアル内。紫はナオミチ追記で可。デフォルトにはしない。

## 書体

指定は **HG創英角ポップ体**。メニューに似た名前が3つある。使うのは HG のみ。

| メニュー名 | 違い | 今回 |
| --- | --- | --- |
| HG創英角ポップ体 | 和文も欧文も等幅 | これを使う |
| HGP創英角ポップ体 | 和文も欧文もプロポーショナル | 使わない |
| HGS創英角ポップ体 | 欧文だけプロポーショナル | 使わない |

Windows の一覧では「HG」の直後に空白が入って見えることがある。創英角ポップ体で、接頭が HG のものを選ぶ。ファイル名 `HGRPP1.TTC` は二次情報。`C:\Windows\Fonts` の実名を正とする。

HG は Windows 標準ではない。リコーの書体で、Microsoft Office 搭載書体としてリコーの販売ページに載っている（2026-09-23 に https://rpc.ricoh.com/products/font/pc を確認）。箱にも Mac にも無い、という現場報告と一致する。

### A. Windows の Fonts（最初にここ）

1. 箱のエクスプローラーで `C:\Windows\Fonts` を開き「創英角ポップ」で検索する。
2. HG創英角ポップ体があれば、その Windows に入っている Filmora 有料版か Premiere で編集する。フォントファイルを Mac へコピーしない。
3. 無い場合だけ B へ。

### B. Office の入り方を見る

Word → ファイル → アカウント。

- 「クイック実行」（デスクトップ版）なのにフォントが無い: Office のクイック修復、ダメならオンライン修復。修復後に Fonts を再検索する。
- 「Microsoft Store」: コミュニティ回答では、ストア版はフォントが少なく、雲マークのフォントはライセンス内のダウンロードで出ることがある（Microsoft Q&A。公式仕様としては未確認）。雲マークの HG創英角ポップ体があるときだけ、そのクリックで入れる。雲が無いものを外部から補わない。
- Office 自体が無い、または修復しても出ない: C か D。

旧来の Microsoft「Office JIS90 互換フォント」（HG45.msi）は、今回公式ページを開けず生死を確認していない。入手口にはしない。

### C. 正規購入（最終手段）

リコーの PC 用ライセンス。ページ記載は端末1台・1書体 19,800円（税込）、商用ライセンス込み（2026-09-23、上記 URL）。

フォントファクトリーの同名商品も税込 19,800円、Windows 10以降と Mac OS X 10.9以降、HG / HGP / HGS を1つの TTC に収容、商用ライセンスつき（2026-09-23 に https://www.fontfactory.jp/font/detail/hgsoeikakupoptai/ を確認）。

案件単価はマニュアル記載の 300円税込/本。19,800円を払うかは司令部の判断。本数が少ないうちは D を先に送る。

Mac で使うなら、Mac 向けの正規ライセンスをその Mac の台数分買う。Windows の Office から抜き出したファイルを Mac に入れない。リコーは、正規購入以外の経路でファイルを持っている場合、用途によって別途商用ライセンスが要ることがある、と書いている。

### D. クライアントへ確認（購入の前）

Teams に送る。レイアウトはこちらの判断として書く。書体だけ返信を待つ。

```
お世話になっております。
マニュアル指定の「HG創英角ポップ体」について確認です。

編集に使う Windows と Mac のどちらにも、この書体が入っていません。
Windows 標準のフォントではなく、Microsoft Office（日本語版）に付属する書体です。
ライセンスの確認が取れないサイトからはインストールしません。

次のどれかで進めさせてください。

1. 指定書体のまま進める
   正規の Office 入り Windows で編集するか、リコーの正規ライセンスを購入してから1本目を作ります。

2. 代替書体を指定いただく
   候補は次の2つです。指定書体と同じ形ではありません。
   - 源ノ角ゴシック Heavy（オープンライセンスで商用可）
   - メイリオ ボールド（Windows に入っている書体）
   使ってよい書体名を返信ください。

3. フォントファイルを支給いただける場合
   御社のライセンスで編集担当へ渡してよいときだけ、Teams でください。
   渡せない場合は、この選択肢は不要です。

レイアウトは、参考の完成例に合わせます。
上下に黒い帯を残し、タイトル2行の直下に動画を置きます。
画面いっぱいに動画を引き伸ばす形にはしません。
書体の返信をいただいてから1本目を納品します。
```

代替を勝手に納品へ使わない。試作の M PLUS Rounded 1c も代替にしない（丸ゴシックで、角ポップではない）。

サイズはマニュアルのまま。タイトル 48〜56 で枠内最大。本文 40〜48。黒縁の太さはマニュアルに px 指定が無い。参考 mp4 に目視で合わせる（数値は推測で固定しない）。

## テロップと音声

原則: **1行＝その行を言っている間だけ。** 2〜3秒は目安であり、固定タイマーにしない。短い行を2秒に伸ばさない。長い行を3秒で切らない。台本の行はまとめない。文言も変えない（マニュアル: 台本は触らない）。

タイトルは全編出す。マニュアルに「常時か、行ごとに消すか」の明文は無い。参考完成例の体裁に合わせた判断（この1点は推測）。

### Filmora / Premiere（納品の本線）

手元 Mac は Premiere Pro 2025（EDIT_SPEC）。書体が Mac に正規インストールできるまで、テロップの本仕上げは書体がある側の PC で行う。Filmora は有料版のみ。無料版の透かしはマニュアルで不可。

1. ナレーションを音声トラックへ置く。B-roll の音声はタイムラインに置かない。音量ゼロではなく、音声クリップを載せない。
2. 台本1行につきテキストを1つ作る。
3. 再生し、その行の第一音でイン、次の行の第一音でアウト。Premiere は第一音でマーカー（M）を打ち、テキストの端をマーカーへ吸着させる。
4. 聞きながら端を動かす。均等割りで端を揃えない。
5. 映像を隠し、音声だけで通しを1回聞く。次の文が始まっているのに前の行が残っていたら直す。無音のうちに次の行が出ていたら直す。
6. 効果音は動作の瞬間に置く。ナレーションは消さない。マニュアルどおり、本人インタビュー等以外の素材音はオフ。

読めないほど短い行、または 55〜56秒に収めると早口になる場合は、マニュアルどおり Teams で連絡する。速度で詰め込んで納品しない。

### ffmpeg（試作側。発話メモが揃ってから）

文字数按分の `timing_plan` は使わない。

1. ナレーションを聞き、台本の各行に「言い始め」「言い終わり」を小数1桁の秒で書く。行数は台本と一致させる。
2. 前の行の終わりと次の行の始まりは同じでよい。重なりは作らない。
3. 各行の PNG を、その秒の `enable='between(t,start,end)'` で乗せる。タイトルは 0 から音声の終わりまで。
4. 書き出し後、各行の開始直後のフレームを抜き、その行の文言だけがあることを見る。次行の開始では前の行が消えていること。
5. `ffprobe` で 1080x1920、尺が音声と一致、音声ストリームがナレーション1本、を確認する。B-roll 側に音声ストリームが残っていたら出し直す。

フレームの抜き方:

```
ffmpeg -y -ss <start> -i out.mp4 -frames:v 1 check_<行番号>.jpg
```
