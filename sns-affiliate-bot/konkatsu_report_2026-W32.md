## 2. 最も効果的だった投稿タイプと理由

### 🥇 trust_building（信頼構築型）が唯一機能しているタイプ

**上位投稿分析：**

```
1位：年齢のせいじゃなかった    → 402views / ER 0.75%
2位：婚活やめたいと思った日    → 335views / ER 0.60%
3位：夜中に泣いた話           →  93views / ER 1.08%
4位：100人会ってわかったこと   →  84views / ER 1.19%
```

### なぜこのタイプが効くのか（3つの理由）

**① 「否定からの解放」フレームが刺さる**
「年齢のせいじゃなかった」は、ターゲット（30代婚活女性）が心の奥底で信じたいこと＝「私が悪いんじゃない」を代弁している。Threadsのアルゴリズムは**滞在時間**を重視するため、自分ごと化できる投稿は有利に働く。

**② 「感情的な体験の具体性」がスクロールを止める**
「婚活やめたいと思った日」「夜中に泣いた話」は、体験の**場面・感情・時間軸**が想起しやすく、同じ経験を持つユーザーの共感スイッチを押す。婚活系コンテンツにおいて「私も同じだった」という感覚はフォロー動機の最大要因。

**③ ミキのペルソナと完全一致している**
34歳・6年間・100人超という「圧倒的な当事者性」がtrust_buildingと化学反応を起こす。adviceでは「また専門家ぶったアカウント」と受け取られるリスクがあるが、trust_buildingでは「同じ経験をした先輩」として機能する。

## 3. 改善が必要なタイプと具体的改善案

### 🔴 Problem 1：adviceタイプの機能停止

**現状：** 16views / 0likes / ER 0.00%
タイトルが空白という致命的な問題があるが、根本的にはタイプ設計自体に課題がある。

**原因分析：**
- フォロワー数が少ない現段階では「情報提供型」投稿は拡散されにくい
- ミキの信頼残高がまだ十分に積まれていないため、adviceが「上から目線」に見える
- Threadsはtwitterと異なり**感情共鳴型コンテンツ**が拡散されやすいプラットフォーム特性がある

**具体的改善案：**

```
【改善前】adviceタイプをそのまま継続 ❌

【改善後①】trust_building内にadvice要素を埋め込む ✅
構成例：
「〇〇で失敗した私が気づいたこと」
↓ 感情的な体験談（3〜4行）
↓ 「あのとき知りたかったこと」として自然にノウハウへ移行
↓ 「今婚活中のあなたへ」で締める

【改善後②】adviceはリプライ・引用リポストで展開する
本文でtrust_buildingして、リプライ欄でadviceを補足する
→ ERとリプライ数を同時に改善できる二段階戦略
```

### 🔴 Problem 2：ビュー数5〜15の低パフォーマンス投稿群

**該当：** 「メッセージで消耗した2年間」「プロフ修正しても変わらなかった」「自分を偽って疲れた」「6年間で失ったもの」

**共通する問題点：**
- タイトル（冒頭）が**「消費・疲弊・喪失」の負のキーワード**で終わっており、クリックモチベーションが生まれない
- 「何が分かるのか」「読んだら何が得られるのか」が見えない
- 暗さだけで**転換（逆転・気づき・希望）**の匂いがしない

**改善フレームワーク：**

```
❌ NG：「6年間で失ったもの」
       （喪失感で終わる→読者に希望を与えない）

✅ OK：「6年間で失ったと思ってたものが、実は〇〇だった」
       （逆転フレーム→続きが気になる）

❌ NG：「メッセージで消耗した2年間」
       （疲弊感のみ→共感はされるが離脱される）

✅ OK：「メッセージ2000通送って気づいた、やってはいけないこと」
       （数字＋学び→情報価値が生まれる）
```

### 🟡 Problem 3：リプライゼロ問題

**対策：投稿末尾に「問いかけ文」を必ず設置する**

```
現状の締め方（推定）：体験談を語って終わり
              ↓
改善後の締め方：
「あなたは婚活中、年齢を言い訳にしたことありますか？」
「同じ気持ちになったことある方、↓で教えてください」
「今日のこれ、誰かに当てはまりますか？」
```
