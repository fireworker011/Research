# 同人成人ゲーム工場（判断用）

量産・ウディタ・RPG化の前にこれを使う。実行本体は `doujin-game-factory/`。

## 先に疑うこと

- 「仕組みが無い」は、売れない原因ではない。出荷ゼロなら需要も品質も未測定。
- 「ウディタが理想」は制約（ほぼPC不可）と衝突する。Editor.exe は Windows。Cloud Agent は Linux。`-txtinput` なしに `.mps` は公式経路で書けない。
- 「週1」は DLsite の **AI生成作品 月3申請** と衝突する（申請日基準、複数サークル回避は公式が不可）。FANZA のゲーム行は公式表で月2に見えるがセル結合のため未確定。
- 「RPG」は工数最大。売れている同人成人ゲームの多くはCG/ADV比重。RPG戦闘は最初の検証物にしない。
- 累計販売中央値（例: ゲーム403本）を月次売上に使うな。
- Xの人気と販売事実を混同するな。本スキル適用時、X MCP が未認証なら「調べていない」と書け。

## 変えられない制約

- 成人向けは登場人物 18+ かつ見た目成人。学生・ロリショタ語は本パイプラインで拒否。
- AI利用は申告。無申告はアカウントリスク。
- 秘密情報をリポジトリに置かない。
- いいね/フォロー自動化や人間偽装は別事業でもやるな。

## 変更できる前提

- エンジン（IR → HTML が先、ウディタは last mile）
- 本数ペース（週1を捨てて月1〜3）
- ジャンル（RPGではなく短い成人ADV）
- 月200万を初月KPIにしない

## ゲート（数字を発明するな）

1. IR が `node src/cli.js generate` を通る
2. HTML プレビューを人間が最後まで触る
3. サークル登録とAI申告文が用意できる
4. 初作30日の実販売本数が 30 未満 → 量産しない
5. プラットフォーム月次キャップを超える計画は棄却

月200万を語るとき（取り分は推定、公式卸価格表が正）:

- 売価2200円・取り分0.6なら 1本あたり1320円。200万円には約1516本/月。
- 月3本なら1作あたり約505本。未出荷の人間がこれを計画値にするな。

## コマンド

```bash
cd doujin-game-factory
node --test
node src/cli.js generate --seed data/seeds/sample-adult-adv.json
node src/cli.js preview --in output/ir/game.json
node src/cli.js woditor --in output/ir/game.json
node src/cli.js gate --price 2200 --copies 0 --works 0
```

## 人間が承認すること

- 販売ページのAI申告区分
- 画像・声・実在人物に似せないかの最終目視
- Editor.exe でのパッケージ化
- 「需要がある」という判断（本数が無いのに承認するな）
- 月次本数をキャップ以上に上げること（承認してもPFが殺す）

## やってはいけないこと

- 検品をスキップしてLLM本文を直販
- 未成年に見えるキャラの「グレー」
- 複数サークルで月次上限回避
- プレビューHTMLを完成RPGだと報告する
- 動画キャッシュループやアフィ投稿ワークフローにこの工場を繋ぐ
