各チャンネルの Shorts タブを yt-dlp の flat playlist で先頭最大30本取り、再生数の中央値と平均を出した。30本に満たないチャンネルはその件数。この標本の中央値の5倍以上、かつタブ再生が1万以上を「大きく伸びた」とした。平均は突出に引っ張られるので、倍率は中央値で割った。タブの再生数は YouTube が表示を整数化したもので、万の位で丸まっている行がある。ページの `viewCount` は同じ動画の Shorts HTML から別途読んだ。

尺は同じ HTML の `lengthSeconds`。公開時刻は同じ HTML の `publishDate`（末尾 -07:00）。

## 2. 現行の金メモが、この標本と違うところ

現行は queueB の kane-07（30.0秒、折り紙、折り目に字幕、声は Keita +45%、BGM なし、最後2秒が PR）。本編のフレームは見ている。

- 最初の台詞が制度の名前「子ども・子育て拠出金。」である。上の8本の題は、10円と97万円、手取り11万、年収1700万、年収の壁、給料日、年金をいつ貰うか、のように金額か生活の一点から始まっている。
- 絵が二つ折りの紙とビル1枚である。上のサムネは話者、手元、硬貨、料理だった。紙の図解は無かった。
- 0.36 を14行で説明する。標本で倍率が一番大きかったのは5秒で、題は一つの金額だった。60〜95秒で中央値を超えたものは、話者か食事か給料日の記録だった。
- 字幕が折り目の細い帯にある。サムネ側は短い文句が大きい。
- 顔も手元も、視聴者が持っている物も出ていない。

## 3. 試作で採った型

勝っていた絵は人物か実物で、この環境では撮影できない。いらすとやには戻していない。コードで試せる範囲は、最初の瞬間を数字にすることと、1本を1つの率にすることまでにした。

台本は新しい。声は `ja-JP-KeitaNeural`、rate +45%（edge-tts）。現行の音声ファイルは使っていない。

画面と字幕:

1. 9.15パーセント。
2. 会社員の厚生年金で、本人が払う率。
3. 会社も、同じ率を払う。
4. 合わせると、18.3パーセント。
5. 標準報酬と、賞与にかける。
6. 平成29年9月から、この率で固定。

根拠は日本年金機構の「厚生年金保険の保険料」（保険料率は平成29年9月を最後に18.3%で固定、事業主と被保険者で半分ずつ）と、厚生労働省の「年金制度の仕組み」（本人負担は9.15%）。同じ機構の「保険料の計算方法」は、端数処理で本人負担と事業主負担の円が1円単位では一致しないことがある、と書いている。画面は率だけにして、明細の円は書いていない。私学共済の料率は別なので、台詞は会社員の厚生年金に限った。

BGM は `scripts/make_bgm.py`（NumPy と SciPy、既存曲のサンプルは使っていない）。話している区間の RMS 比は `public/bgm-level.json` で 0.150（声 0.1114、BGM 0.0167）。

PR は最後の60フレーム（2.0秒）だけ。文言は「#PR」と「PR｜広告を含みます」。本編に誘導文は無い。

## 現行版との比較

見やすさ。試作は数字が画面の中央に大きく、字幕は下の帯にある。現行の kane-07 は折り目の細い字幕と、開く紙の 0.36 が同時に動く。数字を先に読むなら試作の方が画面は単純である。ただし上の標本で再生が中央値を超えた絵は、この文字カードではなく人物か実物だった。

制作時間。現行 queueB の作業時間はリポジトリに無いので、時間の差は置かない。この試作の 426 フレームの書き出しは、この環境で1分未満だった（Remotion 4.0.537、concurrency 2）。その前に、料率の確認と音声生成がある。

量産。台詞と図の文字を差し替えること自体は、このプロジェクトの定数を変えればできる。伸びた型の絵（話者、手元、食事、硬貨）は入っていない。公式の数字を毎回確認する作業は残る。

コスト。声は edge-tts、絵と書き出しはローカル、BGM は自作でライセンス音源は使っていない。新しい有料 API は呼んでいない。円の金額は置かない。

全ラインへ広げるか。広げない。この1本は、数字を先に出す文の形をコードで試しただけで、標本の絵は再現していない。再生もクリックもまだ無い。人がこの mp4 を見て、撮る型（人物か実物か、文字のままか）を決めてからが次である。
