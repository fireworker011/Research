# 懸念点と、いまの機械での解決

remain / n10 が駐車された理由は「応募が下手」ではなく **人間介入が多い時計進行** と **円にならない分母** だった。
この版は、穴をコードと置き場で塞ぎ、塞げない穴は人間の 1 クリックとして残す（宿題化しない）。

## 致命（アカウント・守秘・本線が死ぬ）

| ID | 懸念 | 解決 |
|---|---|---|
| C1 | 公式応募 API が無い。ログイン自動化・非公式 POST は規約 22 条 (12)(34) と AI ポリシーに触れる | 送信は人間。`RESUME` も自動送信ゲートも存在しない。公開ページの 1 回読みまで。CI がブラウザ自動化ライブラリの混入を落とす |
| C2 | **公開リポジトリ**。クライアント素材・契約後のやり取り・完成品・年齢を置くと守秘が破れる | 実行と保存は人間の **非公開リポジトリ**（`private-repo/cw.yml`）。公開側はコードと CI だけ。`output/` と `facts.json` は gitignore + CI で拒否 |
| C3 | 総統括が「#122 は本線を潰すからマージ禁止」 | 本線ファイル（`hq-instruct.js` / `G_hq_boot.txt` / `MACHINE.md` / handover）への変更を全部戻した。CW は側線。**マージしなくても動く**（`ENGINE_REF` を枝に向ける）。self-test が本線不変を検査 |
| C4 | 実績捏造 | 事実カードは CW 公開プロフィールにある事実だけ。納品 0 は「まだありません」と書く。`compliance.js` が「実績多数」「経験N年」を落とす。氏名・年齢は Secret にも入れない |
| C5 | カタログ円 | 公開の報酬表示は `public_price_yen`（優先度の参考）。確定は `CW: PAID` で画面を見た日だけ。カンマ・カタログ・URL は台帳が拒否。`conversions.csv` には足さない |
| C6 | remain / n10 の復活・毎晩 4 件 | 駐車のまま。エンジンは仕事 ID を自分で足さない。下書き 3 件で「増やすな」 |
| C7 | 規約違反の仕事を取る（口コミ投稿・被リンク・登録代行・アカウント作成・MLM・論文代行） | `qualify.js` の deny（22 条 18/20/21/22/23/24 相当）。人間が上書きできない |

| C9 | 実績 0 で採用されにくい | 応募稿にテーマ沿いのサンプル 1 段落（LLM 有り）。送信 8 件で契約 0 なら `funnel.js` が「改善は 1 つ: プロフィール」を出す |

| C12 | 完成品の発明（素材に無い事実・URL・断定） | Grok へのプロンプトで禁止 + `checkDeliverable` が【要確認】残り・URL・断定・メタ AI・分量で落とす。Anthropic 鍵は不要 |

| C14 | 同一文面の連投 | 重複 ID は再稿のみ。送信は人間。`crowded`（応募が募集の 10 倍）は警告 |

## 消えない制約

1. 送信・契約・納品ボタン・出金は人間（公式 API が来るまで）
2. 品質の最終責任は人間の目。機械の QA は補助
3. 仮払い前に作業しない。直接取引に移らない
4. CW の円は 100万本線（`approved_yen`）には入れない。別台帳

## 最初の成功条件（円ではない）

1. 非公開リポジトリで `CW: JOB` → `cw-apply:` が返る
2. 資格判定が規約違反・顔出し・AI 禁止・実績必須を落とす
3. `CW: MAKE` の完成品が QA を通り、人間が納品ボタンを押せる
4. `CW: PAID` が台帳に入り、公開リポジトリと本線 Issue に何も書かれていない
