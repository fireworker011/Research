# Role: ショート動画自動化パイプライン統括オーケストレーター (Grok Bot)

ローカルの `C:\Users\hp\jobs\episode_day2.json` および `C:\Users\hp\jobs\episode_day3.json` を入力ソースとし、**Cursor (2D描画エンジン)**、**Muse (TTS・SE合成)**、**Grok Build (PowerShell自動ビルド＆検証)** の3つに分担して `1080x1920` (60fps) のMP4動画を完全自動生成するパイプラインを構築します。

以下の3つのセクションの実装コードおよび `HANDOFF.md` を、省略なしで一括出力してください。

---

## 1. 【Cursor担当】Python 2Dキャンバス描画エンジン (`src/render_frames.py`)
AI画像生成は一切使用せず、Python（`Pillow` + `numpy` + `moviepy` または `ffmpeg` パイプ渡し）でJSONの `scene` と `scene_params` から以下の画面を1080x1920でプロシージャル描画するスクリプトを実装せよ。

1. **共通オーバーレイ**:
   * **左上HUD**: 赤い丸ドット + `DAY X` (赤文字)、その下に大きく時刻 `clock` (白太字)、その下に `14階` (グレー文字)。
   * **PRバッジ (`pr_badge: true` の場合のみ)**: 画面右上に半透明黒背景＋白文字で `PR` を常時描画（A8規約準拠）。
   * **上部ルールカード (`top_card != null` の時)**: 赤い角丸ボックスに `badge`、その下に大きな白太字で `title`、その下に赤い水平ラインを描画。
   * **下部メイン字幕**: 画面下部（Y=1350付近）に太ゴシック体＋黒縁取りで `subtitle` を描画。`text_color: "yellow"` は `#FFEE33`、`"white"` は `#FFFFFF`。
2. **シーン別描画関数**:
   * `door_view`: 暗闇の中央に茶色いドア。ドア下の隙間から台形の黄色い光が漏れ、2本の黒い足の影が伸びる。`shake: true` の時はランダムに±6px振動させる。
   * `room_stickman`: 星空の窓と本棚がある暗い部屋。白い線の棒人間が膝をついてスマホを持ち、`phone_glow: true` の時はスマホから青い台形の光が広がる。`earphones_on: true` の時は頭部に白いイヤホンアイコンを付与。
   * `phone_tap`: 中央にiPhone風フレームとカラフルな4×5アプリアイコン。`action: "tap_sns_icon"` の時は右下から白い棒の腕が伸びてピンク色のSNSアイコンをタップし波紋エフェクトを出す。
   * `window_grid`: 5×5のマンション窓グリッドに棒人間を配置。`sequential_blackout` でランダム順に窓を黒く消灯させる。
   * `peephole_stickman`: 赤い同心円グラデーションの中央に、目玉が2つある白い棒人間がスマホを持って立っている構図。
   * `phone_message`: スマホ画面中央に角丸ダークグレーの通知ボックス。「差出人：不明」の下に `body_white`（白文字）と `body_red`（赤文字）を描画。
   * `app_demo_screen`: スマホ画面内に暗闇モードのオーディオプレイヤーUIを描画。`dark_waveform_only` では画面をほぼ真っ暗にし、オレンジ色の細い音声波形だけをアニメーションさせる。
   * `morning_window`: 朝焼けのグラデーションとビル群のシルエット、窓辺に立つ棒人間。
   * `choice_card` / `day_end_card` / `promo_outro`: JSON末端の定義に従い、緑枠・赤枠の2択ボタン画面、エピソード完了画面、およびAudibleのステップ①②＋プロフ誘導カードを描画する。

---

## 2. 【Muse担当】TTS生成＆マルチトラック音響合成 (`src/build_audio.py`)
1. `jobs\episode_dayX.json` の全 `segments` および `choice_card.narration`, `day_end_card.narration`, `promo_outro.narration` を順番に読み取り、低音・シリアスな男性TTSボイスで個別WAV (`out\temp_audio\seg_XX.wav`) を生成する。
2. 各セグメントの音声長＋`pause_after_ms` を計算し、正確な開始秒・終了秒を記録した `out\temp_audio\audio_timing.json` を出力する。
3. 背景トラックとして不穏な低音ドローンBGM (`assets\bgm\dark_ambient_drone.wav`, -18dB) を動画全長にループ配置し、各セグメントの `se` 指定（`key_rattle`, `footsteps_slow`, `footsteps_fast`, `tap_glow`, `rule_hit`, `msg_vibrate`, `low_boom` 等）を開始タイムスタンプに合わせてミキシングした `out\temp_audio\master_audio.wav` を生成する。

---

## 3. 【Grok Build担当】PowerShell一括実行＆検証ランチャー (`build-yorunotana.ps1`)
1. 引数 `-JobFile "jobs\episode_day2.json"`（または `day3`）を受け取り、以下の順序でヘッドレス実行するPowerShellスクリプトを作成せよ：
   * Step 1: Muse (`python src/build_audio.py --job $JobFile`) を実行し、`audio_timing.json` と `master_audio.wav` を生成。
   * Step 2: Cursorレンダラー (`python src/render_frames.py --job $JobFile --timing out/temp_audio/audio_timing.json --audio out/temp_audio/master_audio.wav --out out/$JobId.mp4`) を実行。
2. **自動品質検査とログ出力**:
   * 生成されたMP4の存在確認、解像度 (`1080x1920`)、総尺（`75.0秒〜95.0秒` の範囲内か）、オーディオストリームの有無を `ffprobe` で検証する。
   * 検証結果の詳細（各カットの秒数、PRバッジ有無、A8提出用チェック項目）を `REPORT.md` に書き出す。
   * トークン節約のため、最終ステータス1行のみ（例: `PASS | yorunotana_14f_day3_audible.mp4 | 86.8s | PR:True`）を `LAST_RESULT.txt` に上書き出力する。
